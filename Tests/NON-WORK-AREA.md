## Behavior

- **Add Work Area Rule** retains existing behavior and defaults. Old saves load rules as Work rules.
- Expanded and collapsed cards both show a fixed **Work Area** (blue) or **Non-Work Area** (teal) badge above the editable name, plus a short gear-policy description. Color is supplemental; renaming never removes the type label. Collapsed area/status details retain full hover text.
- **Default to Saved Personal Outfit:** is checked by default for new rules and saves without the setting. Checked: use the automatic pre-work snapshot if one exists; selected apparel and weapons are fallback only when no snapshot exists. Unchecked: return AOM-issued work gear through the existing safe locker transition, then require only the selected apparel and weapons. With no selection, vacated slots can remain empty and personal items still worn stay on. Their quality/condition controls apply to selected stock, not exact saved personal items. Changing the preference keeps snapshots, recalls affected managed sessions safely, and clears obsolete unavailable-gear cooldowns. The collapsed header reflects the selected policy.
- **Remove work outfits...** defaults to **All work outfit gear**, including new Work rules added later. Uncheck All in the selector to choose multiple Work Area rules; no selected rules retains all issued work gear. Choices apply together on closing the selector. Rule identities survive renaming; disabled rules remain selectable and selected deleted identities are retained. Collapsed cards summarize both removal scope and replacement source.
- Per-item issuance records associate exact apparel/primary instances with the Work rules they were issued for, independently of the temporary session. An item shared by recorded sources stays until every source is selected. Personally owned items reused for work are not newly classified as issued. Legacy items without source attribution are preserved in specific-selection mode; All can still return them. This is conservative compatibility, not guessed attribution from matching gear types.
- In specific-selection mode, retained work gear takes priority in its slots. Saved personal items fill compatible slots around it without altering the full saved snapshot; conflicting fallback requirements block entry rather than replace retained work gear. A keep-all handoff also replaces the outgoing temporary restoration target so later idle restoration cannot strip gear this rule retained. Stored attribution survives that state ending and save/load; later work cannot capture retained issued gear as a fresh personal outfit.
- AOM records the full personal outfit before issuing work gear. A saved empty outfit or unarmed primary slot is distinct from no saved outfit. Records survive restoration and save/load; persistent records are preferences, while active transitions own reservations.
- **View snapshots...** lists automatic saved non-work outfits for pawns on the current map, including active workers. Selecting a pawn displays their saved apparel and primary or explains that no snapshot exists and fallback applies. Viewing never captures or replaces gear. Manual prototype records are removed on load; genuine active pre-work snapshots can be recovered, while any restoration already in flight keeps its own state.
- With the checkbox on, a snapshot available, and removal set to All, entry restores exact saved apparel and the exact primary (or none). Extra worn apparel must come off. Specific selections preserve unselected issued gear as described above. Borrowed work gear returns through the source rule's locker; a fresh change uses the Non-Work rule's locker. Personal gear can be elsewhere on the map. Existing safe-removal and locker/storage jobs perform the change.
- While saved-personal preference is checked, a saved but unavailable item never activates fallback. Another pawn's active ownership is respected. Existing bounded restoration recovery remains in use; failed entry gets a cooldown. An accepted tattered-item replacement and explicit Release item update the saved preference.
- When selected-gear mode applies, outgoing Work-rule gear returns before fallback preparation. Gear issued for a Non-Work rule is retained while satisfying that rule. Empty categories permit remaining personal gear or empty slots; the issued work weapon is returned. A transient return target is separate from the stored automatic snapshot, and a persisted flag distinguishes this return from personal-outfit restoration. The return does not erase the stored snapshot. Empty weapon selection does not force removal of a remaining personal primary. The feature cannot infer civilian clothing from a pawn already wearing armor.
- Access groups, work/haul/wander permissions, child work watching, pause, recall, and fallback task buffers reuse existing controls. Saved-outfit entry bypasses the outgoing task buffer; it uses safe recall/restoration and lets native task selection reconsider the activity afterward.
- On departure, normal Work Area rules can issue gear again. This candidate does not introduce a global off-duty/on-duty schedule or automatically re-equip manually issued armor after leaving.
- Incompatible overlaps or jobs requiring both conflicting outfits are blocked with bounded retries. No saved-outfit priority overrides work safety requirements. Late-bound path-cell conflicts are also checked. Compatible overlaps remain valid.
- Area names are arbitrary. Dining rooms, lounges, bedrooms, public meeting rooms, and visitor spaces are examples only.
